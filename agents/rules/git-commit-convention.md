# Git 커밋 메시지 컨벤션

## 형식
```
<type>: <제목>

<본문(선택)>

<꼬리말(선택)>
```

## 타입 목록
- `feat`: 새로운 기능 추가
- `fix`: 버그 수정
- `refactor`: 기능 변경 없는 코드 구조 개선
- `perf`: 성능 개선
- `test`: 테스트 코드 추가·수정
- `chore`: 빌드, 패키지, 설정 등 비기능 변경
- `docs`: 문서 추가·수정
- `style`: 코드 포맷, 들여쓰기 등 스타일 변경 (로직 무관)

## 언어
- 타입 접두사는 영어 소문자로 작성한다.
- 제목과 본문은 한국어로 작성한다.

## 제목 규칙
- 제목은 명령형으로 작성한다. (예: "추가한다" → "추가")
- 제목 끝에 마침표를 붙이지 않는다.
- 제목은 50자 이내로 작성한다.

## 본문 규칙
- 제목과 본문 사이는 빈 줄로 구분한다.
- 본문은 "무엇을" 변경했는지보다 "왜" 변경했는지를 설명한다.
- 한 줄은 72자 이내로 작성한다.

## 예시
좋은 예:
```
feat: 사용자 로그인 실패 시 재시도 횟수 제한 추가

무차별 대입 공격을 막기 위해 5회 실패 시 계정을 잠근다.
```

나쁜 예:
```
update login.js       # 타입 누락, 변경 의도 불명확
fix: 버그를 수정했다.  # 명령형 아님, 마침표 사용
```
