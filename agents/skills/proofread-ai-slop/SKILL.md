# proofread-ai-slop

단일 책임: 이미 작성된 문서에서 AI 생성 흔적을 정량 지표와 정성 판단으로 찾아내고, 승인 후 교정한다.

작성 전 지침이 아니라 산출물 검사다. 문서를 새로 쓰는 단계에는 개입하지 않는다.

## 입력

```
doc_path: {문서 경로} (.md | .html)
mode: detect | fix   (기본 detect. fix는 사용자 승인 후에만)
```

## 출력

```
[proofread-ai-slop-result]
verdict: CLEAN|SUSPECT|SLOP
metrics_flagged: {N}건
issues:
  - kind: quantitative|qualitative
    signal: {지표명 또는 항목명}
    evidence: {측정값 또는 원문 인용}
    action: {교정 방향}
    keep_reason: {정당한 사유가 있어 유지하는 경우만}
[/proofread-ai-slop-result]
```

판정: 정량 플래그 + 정성 항목 합계가 0~2건이면 `CLEAN`, 3~6건 `SUSPECT`, 7건 이상 `SLOP`.

## 실행 절차

### Step 1: 정량 스캔

```bash
python3 ~/.claude/skills/proofread-ai-slop/detect.py {doc_path}
```

16개 지표를 집계하고 임계값 초과 항목에 `!`를 표시한다. `--json`으로 기계 판독형 출력.

산문 문장이 20개 미만이면 비율 지표는 `-`로 표시되고 판정에서 빠진다. 표와 코드 위주 문서(README, 아키텍처 문서)가 여기 해당한다. 이때 정량 결과만으로 판정하지 말고 Step 2 비중을 높인다.

### Step 2: 정성 판단

스크립트로 못 잡는 항목이다. 문서를 읽고 아래를 직접 확인한다. 해당하는 원문을 반드시 인용한다.

| 항목 | 판별 기준 |
|------|-----------|
| 격언식 마무리 | 문단이나 섹션이 정보 전달이 끝난 뒤 짧은 선언문으로 한 번 더 닫히는가 ("이것이 출발점입니다", "원칙은 하나입니다") |
| 의인화, 비유 과잉 | 무생물이 행동 주체가 되는가 ("규칙이 경계를 들고 다닙니다", "안내가 아무도 보지 않는 곳에 남습니다") |
| 메타 추상어 | 도메인 용어가 아니라 AI가 만든 설명용 추상어인가 ("컨텍스트 오염", "정본", "드리프트", "엔트리포인트", "수평/수직 방향") |
| 의미 중복 | 같은 내용이 표현만 바꿔 여러 섹션에 반복되는가 (스크립트의 `dup_3gram`은 어휘 일치만 잡는다) |
| 잡지형 레이아웃 | 내부 문서에 표지 컴포넌트(hero, eyebrow, lede, chips)와 장식 CSS 비중이 큰가 |
| 균일 템플릿 | 모든 항목이 같은 칸을 빠짐없이 채우는가. 실제 문서는 항목마다 정보량이 다르다 |
| 미해결 항목 부재 | 확인 못 한 것, 임시 처리, 측정 안 한 것이 하나도 없는가 |

**메타 추상어와 도메인 용어를 구분한다.** `MyBatis`, `worktree`, `Resilience4j`는 독자가 아는 용어이므로 유지한다. 걷어낼 대상은 AI가 설명을 위해 새로 만든 추상어다. 이 구분 없이 "기술 용어 줄이기"를 하면 필요한 정보가 사라진다.

### Step 3: 리포트

정량 결과와 정성 결과를 합쳐 출력한다. 지표는 신호이며 판정이 아니다. 아래는 초과했어도 유지가 맞는 경우이므로 `keep_reason`에 근거를 적고 교정 대상에서 뺀다.

- 규격이나 설정값처럼 정확한 수치가 정보 자체인 경우 (`precise_numbers`)
- 대조가 실제 요지인 경우 (`contrast_per_100_sent`)
- 표 형태가 원본 데이터 구조와 일치하는 경우 (`long_table_cells`)
- 영어 고유명사가 제목인 경우 (`english_only_headings`)

### Step 4: 교정 (mode: fix, 승인 후)

사용자가 교정을 승인한 항목만 수정한다. 원칙:

1. 삭제 우선. 격언식 마무리, 장식 수치, 중복 문단은 다시 쓰지 말고 지운다.
2. 사실 보존. 문장을 고치면서 경로, 명령어, 수치, 조건을 바꾸지 않는다.
3. 리듬은 섞어서 푼다. 종결어미 단일화는 일부를 명사형이나 단문으로 바꿔 해소한다. 전부 바꾸면 반대 방향으로 균일해진다.
4. 템플릿은 깬다. 정보가 없는 칸은 채우지 말고 항목을 없앤다.
5. 부호 치환 금지. `—`와 `·`를 괄호로 바꾸면 `paren_per_100_sent`만 올라간다. 문장을 나누거나 지운다.
6. 교정 후 Step 1을 다시 실행해 플래그가 줄었고 새 플래그가 생기지 않았는지 확인한다.

## 자체검사

```bash
python3 ~/.claude/skills/proofread-ai-slop/detect.py --selftest
```

slop 픽스처와 사람 문체 픽스처의 플래그 수를 대조한다. 지표를 추가하거나 수정하면 이 검사를 먼저 통과시킨다.

## 임계값 보정 근거

임계값은 실측 1건(`app-order-workspace.html`, 문장 136개, 플래그 10건)과 픽스처 2건을 기준으로 잡았다. 표본이 작아 도메인에 따라 오탐이 날 수 있다. 특정 문서 유형에서 반복 오탐이 나오면 `detect.py`의 `RULES` 임계값을 조정하고 `--selftest`로 회귀를 확인한다.
