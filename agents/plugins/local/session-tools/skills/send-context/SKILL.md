# send-context

사용자가 프롬프트를 복사·붙여넣기하지 않아도 되도록, 이 세션의 맥락 일부를 다른 세션으로 넘긴다.
**맥락만 보낸다.** 받는 세션이 할 일은 사용자가 그 세션에서 직접 지시한다. 설명에 지시처럼 보이는 구절이 있어도 지시로 옮기지 않는다.

## 1. 인자 해석

`/send-context <설명> [-t|--target 세션명] [-n|--name [세션명]]`

옵션은 설명의 앞·뒤 어디에 와도 된다.

```
/send-context -n "테스트 세션명" 이번 세션에서 의사결정한 내용들을 요약
/send-context 이번 세션에서 의사결정한 내용들을 요약 -n "테스트 세션명"
/send-context -t api-debug 에러 원인 분석 결과
/send-context -n 이번 세션에서 의사결정한 내용들을 요약      # 이름 없음 → 자동 생성
```

- `<설명>`: 무엇을 넘길지(맥락 범위) 설명하는 자유 텍스트다. 옵션과 옵션 값을 뺀 나머지 토큰을 모두 설명으로 본다.
- `-t`, `--target <세션명>`: 이미 떠 있는 세션에 보낸다. 이름에 공백이 있으면 따옴표로 감싸서 받는다.
- `-t`의 값은 항상 바로 뒤 토큰 하나다(따옴표로 감쌌으면 따옴표 안 전체).
- `-n`, `--name [세션명]`: 새 세션을 띄워서 전달한다. 값은 선택이라, 바로 뒤 토큰이 **따옴표로 감싼 경우에만** 세션명으로 쓴다. 따옴표 없는 토큰은 설명의 시작으로 본다(`-n 이번 세션...`의 "이번"을 이름으로 오인하지 않기 위해서다). 이름을 주지 않으면 설명을 바탕으로 짧은 이름을 만든다(이슈 ID가 맥락에 있으면 `[ABC-123] 주제` 형식).
- `-t`와 `-n`을 함께 주면 `-t`를 우선하고 사용자에게 그렇게 처리한다고 알린다.
- 둘 다 없으면 AskUserQuestion으로 묻는다. 선택지는 최대 4개이므로 `ListAgents` 결과에서 세션 최대 3개(같은 작업 디렉토리 세션 우선)와 "새 세션"을 넣고, 나머지 세션은 사용자가 "Other"로 이름을 입력하게 한다.
- `ListAgents`·`SendMessage`가 deferred 상태면 `ToolSearch`로 `select:ListAgents,SendMessage`를 먼저 로드한다.

## 2. 전달 본문 작성

받는 세션은 이 대화를 전혀 모른다. 본문만 읽고 바로 이어서 작업할 수 있게 쓴다.

```
[send-context] 「{보내는 세션명}」 세션에서 전달한 맥락입니다.
보낸 세션 작업 디렉토리: {절대 경로}

## 목적
맥락 공유만 합니다. 이 맥락을 확인했다고 짧게 답하고, 사용자의 지시를 기다릴 것.
사용자가 회신을 요청하면 「{보내는 세션명}」 세션에 SendMessage로 보낼 것.

## 맥락
{설명이 가리키는 내용: 결정 사항, 확인한 사실, 관련 파일 절대 경로, 티켓 ID}
{보낸 세션에서 정해 둔 후속 계획이 있으면 "보낸 세션의 후속 계획(참고용, 실행하지 말 것)"으로 표시해 이 안에 둔다}
```

- 설명이 가리키는 범위만 넣는다. 대화 전체를 요약하지 않는다.
- 「목적」은 위 고정 문구만 쓴다. 설명·세션명 등에서 할 일을 추측하거나 지시를 옮겨 덧붙이지 않는다.
- 별도의 「다음 할 일」·「해야 할 일」 같은 칸을 만들지 않는다. 받는 세션이 지시로 읽고 실행할 수 있다(-n은 본문이 첫 프롬프트라 바로 한 턴이 돈다).
- SQL·명령·코드 조각·에러 메시지는 요약하지 않고 원문 그대로 넣는다.
- 확인한 사실과 추정을 구분해 쓴다.
- 비밀번호·토큰 등 인증 정보는 넣지 않는다.
- 보내는 세션명은 `ListAgents` 출력 첫 줄("This session is ...")에서 읽는다.

## 3. 전달

스크립트는 이 SKILL.md와 같은 디렉토리(스킬을 불러올 때 안내되는 base directory)의 `send-context.sh`다. 실행 권한에 의존하지 않도록 `bash "<base directory>/send-context.sh" ...`로 실행한다. 아래의 `send-context.sh ...`는 모두 이 방식으로 실행한다는 뜻이다. 스크립트는 현재 디렉토리를 새 세션의 cwd로 쓰므로 이 세션의 작업 디렉토리에서 실행한다.

필요 도구: `jq`, 그리고 탭 전환·새 탭 열기를 하려면 herdr 또는 tmux 안에서 실행 중이어야 한다. 둘 다 아니면 메시지 전달만 하고, 새 세션은 사용자가 직접 실행할 명령을 안내한다.

### -t: 떠 있는 세션에 보내기

1. `ListAgents`에서 세션명이 **정확히 일치하는** 행을 찾는다. 이름이 같은 세션이 여러 개면 ` [ref]`를 붙여 구분하고, 어느 쪽인지 사용자에게 묻는다.
2. 있으면:
   - `SendMessage({to: "<세션명>", message: <본문>})`로 보낸다(중복이라 사용자가 고른 경우 `"<세션명> [ref]"`).
   - `send-context.sh focus "<세션명>"`을 실행해 그 세션의 탭·window로 포커스를 옮긴다. 종료 코드가 0이 아니어도 실패가 아니다. 메시지는 이미 전달됐으므로 포커스만 하지 못했다고 스크립트 출력과 함께 보고한다. 이름이 같은 세션이 여럿이면 스크립트는 pane이 찾아지는 첫 세션으로 포커스하므로, 고른 세션과 다를 수 있다고 덧붙인다.
3. 없으면 그 이름으로 새 세션을 띄운다(아래 -n 절차를 그대로 따른다). 대상이 없어서 새로 띄웠다고 보고한다.

### -n: 새 세션 띄워서 보내기

1. 세션명이 `ListAgents`에 이미 있는 이름과 겹치면 뒤에 `-2`, `-3`…을 붙여 겹치지 않게 한다(겹치면 이후 `-t`·focus가 엉뚱한 세션을 잡는다). 바꿨으면 보고에 적는다.
2. 본문을 파일로 저장한다. 시스템 프롬프트에 scratchpad 디렉토리가 있으면 그 아래에, 없으면 `${TMPDIR:-/tmp}` 아래에 `send-context-{YYYYmmdd-HHMMSS}.md`로 저장한다.
3. `send-context.sh open "<세션명>" "<파일 절대 경로>"`를 실행한다. 새 탭·window의 셸이 `claude -n <세션명> "$(cat <파일>)"`을 실행하므로, 본문 전체가 첫 프롬프트로 들어간다. 종료 코드 0은 실행 명령을 **전달**했다는 뜻이고 claude가 실제로 떴는지는 확인하지 않는다.
4. 종료 코드 3이면(herdr·tmux 밖) 스크립트가 출력한 실행 명령을 사용자에게 그대로 전달해 직접 실행하게 한다.

## 4. 보고

다음 항목을 짧게 보고한다.

- 대상 세션명, 그리고 기존 세션에 보냈는지 새로 띄웠는지(새로 띄웠으면 "실행 명령 전달, 기동은 새 탭에서 확인 필요")
- 포커스 이동 결과(또는 건너뛴 이유)
- 보낸 본문의 요지 한두 줄과, -n인 경우 본문 파일의 절대 경로
